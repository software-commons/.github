## Implementation boundaries

- **Per-record versioning.** The registry stores immutable records with stable IDs and explicit revisions. Corrections append new records and dispositions. This limits unrelated changes and preserves the exact predecessor used in a release.
- **Review as a separate input.** Machine validation consumes review and acquisition records. It cannot create them. The verifier makes independent retrievals and records positive, negative, or inconclusive assessments. Git review and access to the originating run establish accountability for attestations.
- **Shared contracts with local predicates.** The standard controls scope, authority, integrity, and eligibility. Each index owns its own vocabulary and describes the dimensions required by each predicate. The shared validator uses explicit exact compatibility rules and leaves semantic judgment to direct review.
- **Publication from an explicit selection.** A checked selection produces the canonical bundle. Preserve rejected and exploratory material in the registry, where it remains distinguishable from qualified outputs. Consumers can compare digests and inspect the inputs for the named release.

## Alternatives evaluated

- A source rank or agreement threshold would conflate epistemic role with evidence quality, and mirrors or common infrastructure could inflate agreement.
- One consolidated evidence file would simplify initial loading but increase merge contention and make it harder to protect revisions independently.
- A universal ontology or network-dependent validation gate would couple index implementations and make local rebuilds dependent on mutable service responses. Review performs source retrieval. The deterministic gate verifies recorded bytes and relationships offline.
- A self-attesting agent workflow would allow one execution to write the claim and manufacture its own verification. A fresh run with its own acquisition and review artifacts enables auditing while preserving the distinction between autonomous review and human review.
